Author of Code: John
Code Under Review: Party Member Battle Classes for Readability
Time: 4 Minutes
The code is fairly readable overall though a few changes could be made to improve it further. These primarily
consist of creating a few more helper functions along with altering the levelUp system to not require 9 arguments.
For the helper functions, it seems that a lot of the attack consist of a change in the math of the game then a display
to the user of what math was done. I think by putting these two separate actions into different functions it would
improve the readablitiy of the various special attack and maybe allow for less repeated code. In terms of the levelUP
system 9 arguments makes it hard to know what stats are correlated to which arguments. A potential solution could be
to have the default leveling being it's own function stored in Player. Then specific stat changes are called individually.
This would likely require stats to be a dictionary which I think might be better overall since, playerStats has a lot
of file scope variables as is.

Code under Review: MenuState for code quality
Time: 5 minutes
Once again, omitting InitializeUI the quality doesn't seem bad. Coupling with KeyboardState is not good, but we did it for
time crunch reasons. However, the elephant in the room is InitializeUI. The team strugged with UI creation both in MenuState
and in BattleState. I don't think any of us were prepared for how complicated that method needed to be, and by the time we
realized, it was far too late for this sprint. This would need to be cleaned up into many methods, or, as John said about
BattleState, the UI initialization could be given its own class entirely. I also would like to see a bit more code reuse
when constructing UI components. The factories that we have are decent, but I think they could encapsulate more. Finally,
we have a problem with lambda functions getting way inflated for button response. These lambdas need to be changed to more
structured delegates, running named functions, and some of the response should be handled in some kind of a controller.
